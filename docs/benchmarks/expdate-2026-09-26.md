# ExpDate diagnostic — 2026-09-26

This is an external dataset diagnostic, not the medicine benchmark gate in
[ROADMAP](../../ROADMAP.md). The evaluator and protocol are documented in
[datasets/README](../../datasets/README.md#evaluate-the-downloaded-expdate-archive).
It compares OCR transcriptions and printed ISO dates, not legal `valid_through`
semantics or accuracy on Russian medicine packaging.

## Data and provenance

Source: [ExpDate](https://felizang.github.io/expdate/index_expdate.html), accessed
2026-09-26. Credit: Ahmet Cagatay Seker and Sang Chul Ahn, Korea Institute of
Science and Technology (KIST). Associated publication: *A generalized framework
for recognition of expiration dates on product packages using fully
convolutional networks*, Expert Systems with Applications 203 (2022), 117310
(citation supplied by the dataset page). Dataset license:
[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).

Input: the evaluation split in the maintainer's `Products-Real.zip`, SHA-256
`31dff6e0045ab6f4683c9e20b5dd04fedd751c174b681193744a013637e38da6`.
The training split is not used. Images remain outside Git. Oracle crops are
temporary in-memory crops of upstream expiry boxes, padded by eight pixels on
each side and clipped to image bounds.

## Method

- Full-frame OCR uses the installed RapidOCR backend with barcode reading off.
  OCR detections overlapping the annotated expiry region are used for
  normalized transcription matching. Punctuation, spacing and case are
  ignored; digit/letter substitutions are not corrected by the scorer.
- The same OCR detector and recognizer run on each oracle crop. This is a
  specific crop procedure, not a learned detector or a recognition-only upper
  bound. Losing surrounding context and rerunning detection can hurt results.
- Upstream DMY components supply expected printed ISO values independently of
  packdate. Missing components, inconsistent transcriptions and invalid dates
  are excluded from ISO scoring, not treated as negatives. Month labels retain
  month precision. Two-digit years use the explicit diagnostic convention 20YY.
- The initial parser is the source at Git revision
  `bbfae62`. The second evaluation replays exactly the same saved full-frame
  OCR text through the year-first full-date fix. No EXP cue or annotation is
  inserted into runtime parser input.
- Full JSON reports record model hashes, resolved backend configuration,
  package versions, source hashes, per-image outputs and data hashes. Text-only
  replay records its new parser hashes separately and does not reconstruct
  result bounding boxes.

one remains incorrect because OCR read `2022.06.15` as `2022.06.5`

Candidate availability improves even when the parser correctly keeps its
expiry-cue requirement: 395 of the post-fix abstentions have `no_cue`.

Therefore, this specific crop-plus-redetection procedure does not improve this
baseline; a different recognition-only crop experiment remains untested.

## Interpretation and next work

The year-first fix preserves the day in `YYYY.MM.DD`, `YYYY/MM/DD` and
`YYYY_MM_DD`. For example, `test_00059.jpg` contains
`Best before: 2022.08.31`; the old parser committed only `2022-08`.
Unit regressions also cover leap years, invalid calendar dates, spacing around
separators and abstention without expiry evidence.

The diagnostic also exposes work deliberately left for separate changes:

1. Review unsupported full-date formats before extending the parser. Examples
   include `APR-28-2023` (`test_00251.jpg`) and `22 06 2022`
   (`test_00248.jpg`), which can currently produce partial month readings.
2. Review upstream labels and date order before treating disagreement as an
   application error. `test_00076.jpg` reads `Best Before: 21.01.22`;
   its annotation specifies 2021-01-22, while the current DMY policy returns
   2022-01-21. Transcription alone does not settle that order.
3. Investigate crop recognition separately from full-frame detection before
   choosing an ROI model. The current crop experiment still reruns text
   detection and is not evidence of a detector's achievable quality.
4. Collect/confirm medicine fixtures, including negatives, manufacturing dates,
   foil, embossing and multiple packages. Many ExpDate photos do not contain a
   RU/EN expiry cue recognized by this parser. Removing the cue requirement to
   raise this score would also permit manufacture/batch dates to be selected.

The upstream labels have not been adjudicated by the maintainer. Numbers from
this run describe agreement with those labels. They do not close the medicine
fixture or milestone 4 gates, and the all-expiry evaluation set does not measure
false positives on negative photographs.

## Reproduce

With the existing OCR extra installed, from the repository root:

```powershell
$env:PYTHONPATH = "src"
.venv/Scripts/python.exe datasets/evaluate_expdate.py Products-Real.zip --oracle-crops --out D:/packdate-data/expdate/cyrillic-current.json
.venv/Scripts/python.exe datasets/evaluate_expdate.py D:/packdate-data/expdate/cyrillic-baseline.json --reparse --out D:/packdate-data/expdate/cyrillic-reparsed.json
.venv/Scripts/python.exe -m pytest -q
$env:PACKDATE_OCR_TESTS = "1"
.venv/Scripts/python.exe -m pytest -q tests/test_ocr_rapid.py
```

The first command runs the current parser; the saved baseline was produced
before the fix, using the parser at `bbfae62`. The second command requires that
completed baseline report. Full reports are local artifacts, not repository
files; archive/model/source hashes in the recorded results identify this run.
